# What changed from 00-billing.velle to 06-payments-positive.velle

This report compares what two versions of a spec say. It describes a system in general,
never the records of a running one. Each line points at the place in the spec that says it.
Where the report has no words for a change yet, it shows the Velle instead and says so.

## What was edited

- LineItem is written differently and means the same, if `velle.finance` is right that the sides may be swapped for `decimal * Money`.
  In the spec: 06-payments-positive.velle, line 46, `act LineItem`
- A Payment is now forbidden when its amount is at most 0.
  In the spec: 06-payments-positive.velle, line 69, `never (Payment where amount <= 0)`
- An Invoice is now a PaidInvoice when its balance is at most 0. Before: when its total is above 0 and its balance is at most 0.
  In the spec: 06-payments-positive.velle, line 88, `shape PaidInvoice = Invoice where balance <= 0`
- A LineItem is no longer refused when its price is below 0.
  In the spec: 00-billing.velle, line 90, `never (LineItem where price < 0)`
- An Invoice is now an ActionableOverdue when it is an OverdueInvoice and it is an IssuedInvoice and it is not an ArchivedInvoice. Before: when it is an OverdueInvoice and it is not an ArchivedInvoice.
  In the spec: 06-payments-positive.velle, line 122, `shape ActionableOverdue = OverdueInvoice and IssuedInvoice and not ArchivedInvoice`
- Reminder is now called Nudge. Nothing else about it changed. Records already stored as Reminder are not carried over by this change.
  In the spec: 06-payments-positive.velle, line 124, `shape Nudge`
- RemindOverdue changed. Now: at each Weekly tick, for every Invoice of which it is true that it is an ActionableOverdue and there is no Nudge whose invoice is it and whose sentOn is after 14 days before today, it creates a Nudge with invoice set to it, sentOn set to today. Before: at each Weekly tick, for every Invoice of which it is true that it is an ActionableOverdue and there is no Nudge whose invoice is it and whose sentOn is after 7 days before today, it creates a Nudge with invoice set to it, sentOn set to today.
  In the spec: 06-payments-positive.velle, line 129, `rule RemindOverdue`

## What that changes

What the compiler derives from the edits for declarations nobody edited. Each is something
that can now happen or can no longer happen; none says what will happen.

### Invoice

- RecordPayment creating a Payment can no longer make an Invoice stop being a PaidInvoice.
  In the spec: 06-payments-positive.velle, line 69, `never (Payment where amount <= 0)`
  In the spec: 06-payments-positive.velle, line 88, `shape PaidInvoice = Invoice where balance <= 0`
- A new LineItem can now make an Invoice stop being an OverdueInvoice.
  In the spec: 06-payments-positive.velle, line 46, `act LineItem`
  In the spec: 00-billing.velle, line 90, `never (LineItem where price < 0)`
- RecordPayment creating a Payment can no longer make an Invoice become an OverdueInvoice.
  In the spec: 06-payments-positive.velle, line 69, `never (Payment where amount <= 0)`

### Issuance

- A new Issuance can now cause RemindOverdue to run, later rather than in the same commit.
  In the spec: 06-payments-positive.velle, line 129, `rule RemindOverdue`

### OpenInvoice

- OpenInvoice can now cause SendReceipt to run.
  In the spec: 06-payments-positive.velle, line 46, `act LineItem`
  In the spec: 06-payments-positive.velle, line 69, `never (Payment where amount <= 0)`
  In the spec: 06-payments-positive.velle, line 88, `shape PaidInvoice = Invoice where balance <= 0`
  In the spec: 00-billing.velle, line 90, `never (LineItem where price < 0)`
  In the spec: 06-payments-positive.velle, line 122, `shape ActionableOverdue = OverdueInvoice and IssuedInvoice and not ArchivedInvoice`
  In the spec: 06-payments-positive.velle, line 124, `shape Nudge`
  In the spec: 06-payments-positive.velle, line 129, `rule RemindOverdue`

### RecordPayment

- RecordPayment can no longer cause RemindOverdue to run, later rather than in the same commit.
  In the spec: 06-payments-positive.velle, line 129, `rule RemindOverdue`

### The spec as a whole

- 2 generated cases are no longer generated: never - a LineItem where price below 0.00 is refused; never - a LineItem with price 0.00 is accepted.
  In the spec: 06-payments-positive.velle, line 46, `act LineItem`
  In the spec: 00-billing.velle, line 90, `never (LineItem where price < 0)`

## What happens to a record like this

What the edits do to a record of the kind the system keeps, worked out from the two specs alone.
It says which kind of record, never which records or how many.

### An Invoice like this

- An Invoice becomes a PaidInvoice by this change alone when its balance is at most 0 and its total is not above 0.
  In the spec: 06-payments-positive.velle, line 88, `shape PaidInvoice = Invoice where balance <= 0`
- SendReceipt could then run for it, with no act or tick causing it.
  In the spec: 06-payments-positive.velle, line 88, `shape PaidInvoice = Invoice where balance <= 0`
- An Invoice stops being an ActionableOverdue by this change alone when it is an OverdueInvoice, it is not an ArchivedInvoice, and it is not an IssuedInvoice.
  In the spec: 06-payments-positive.velle, line 122, `shape ActionableOverdue = OverdueInvoice and IssuedInvoice and not ArchivedInvoice`
- At the next Weekly tick, RemindOverdue no longer runs for it.
  In the spec: 06-payments-positive.velle, line 122, `shape ActionableOverdue = OverdueInvoice and IssuedInvoice and not ArchivedInvoice`

### A Payment like this

- A Payment stored before this change is now forbidden when its amount is at most 0. Its next change could be refused.
  In the spec: 06-payments-positive.velle, line 69, `never (Payment where amount <= 0)`
