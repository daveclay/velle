# examples/

Rules for the example systems. The `implement` skill has the procedure for
regenerating their output.

## What an example is for

An example exists to find what Velle cannot say or says at a cost. The
deliverable of a use-case or stress pass is the list of gaps, each pinned by
a probe, a test, or a `.velle` file that shows it. A finding stands on its
own: never soften or close one by noting that the real-world domain could
live with the limitation. Dave, 2026-10-16: "I don't care about modeling the
real world, I care about gaps in velle." Findings go to
`working-docs/QUESTIONS.md` as items, or to the OQ they belong to.

Examples that probe a gap before it is settled live under
`working-docs/examples/survey/`, one `.velle` file per spelling, named
`<nn>-<topic>-<accepted|refused|workaround>.velle`, with a README line
saying what each produces. They move or are deleted when the gap settles.

## Layout of a module

Each `examples/<system>/` has:

- `<system>.velle`, the spec, which is the source of everything else.
- `output/`, the generated Kotlin, checked in, regenerated by
  `:examples:<system>:output:generate`, with a `CodegenGoldenTest` in several
  modules that fails when the checked-in output is stale.
- `app/`, a Spring Boot application over PostgreSQL: one bean, a
  `compose.yaml` with `postgres:17`, its own port (the table is in
  `README.md`), schedules in `application.yaml`, and a smoke test over
  in-memory SQLite that needs no Docker. Pharmacy and vendors resolve the
  actor from `X-Velle-Actor` and ship bootstrap fixtures; pharmacy's
  `PharmacySeed` walks ninety days of scripted activity through the
  generated acts.

A new example is registered in `settings.gradle.kts` and in the root
`generate` task in `build.gradle.kts`, and gets an `app/` module made from
the billing pattern with the next free port.

Run one with `./gradlew :examples:<system>:app:bootRun`.

## Writing a spec

- A spec reads as the product owner would say it. Every `never` is a
  business rule in the owner's words, with a comment only where the spelling
  is not obvious.
- A seed or fixture obeys the spec's own doors; it goes through the
  generated acts, never around them.
- Billing's amounts are `velle.finance.Money` from `extensions/finance`;
  its output module depends on `extensions:finance` and `finance-sql`.
- When an example is cited anywhere, in a wiki page, an OQ, a test, or chat,
  the citation names the file: `examples/<system>/<system>.velle`, and the
  rule or shape by name.
