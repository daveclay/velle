# Glossary

Coined terms used across the documents, one line each, with the pointer that defines them. Language constructs the Reference defines (shape, refinement, rule, guard, fold, capture, tick, act) aren't repeated here — this covers the working vocabulary invented along the way. Rule of use: a doc's first use of one of these terms should read sensibly to someone who has only this file.

## Acts and the trust boundary

- **Reference / Reference §N** — the Velle [Language Reference](Home#the-velle-language-reference): the numbered pages `Reference-01-Principles` through `Reference-22-Open-unresolved` of this wiki, one per section, cited everywhere (documents, spec comments, validator diagnostics) as "Reference §N" by section number. It was the repository's README until 2026-10-15.
- **act** — a shape declared `act`, whose instances are committed from outside the system; also such an instance, a request or message crossing the trust boundary ([Reference §4](Reference-04-State-and-commits), [§22](Reference-22-Open-unresolved)).
- **transient act** — an act that exists only within its own commit's transaction (`transient act`): an input to the state, not a member of it ([Reference §4](Reference-04-State-and-commits); decided 2026-08-10 on the principle that an incoming mutation is an input to the state, not automatically a member of it).
- **prohibition** — what a `never` or a `requires` declares: a configuration that is impossible, stated as the forbidden configuration (`never`) or as what every record satisfies (`requires`, whose prohibition is its complement; inside a requirement, membership may be spelled `to be`). The umbrella noun (adopted 2026-10-10 in place of "invariant", which named only the proven kind); a prohibition is a refusal, a constraint, or a guarantee, by who it binds ([Reference §21](Reference-21-never)).
- **refusal** — a prohibition that binds the caller: a prohibition over a transient act, checked once — at the door when the request's handling leaves what it reads alone, at the settled transaction otherwise; the record the request leaves carries nothing ([Reference §21](Reference-21-never)).
- **door / door-checked** — the moment right after an act's closure is inserted and before any rule runs, where the prohibitions no rule can move (reading nothing any rule writes, creates, or deletes) are evaluated once and then skipped at the transaction end; a *door-checked* prohibition is one of those ([Reference §21](Reference-21-never); [`evaluation.md` "An exposed call"](evaluation#an-exposed-call); ruled 2026-10-14).
- **constraint** — a prohibition that binds the books: a prohibition over a persistent shape, holding at the end of every transaction for as long as the record exists; any act or tick that would leave the books otherwise is rejected; it may not read the clock, since the books could age into it with no act to refuse ([Reference §21](Reference-21-never); [`checks.md`](checks) [V30](checks#v30--a-constraint-that-reads-the-clock-coarse)).
- **guarantee** — a prohibition that binds the spec's own rules: only rules can produce the state, nobody is refused, and the compiler proves the rules cannot reach it; a runtime violation is a bug ([Reference §21](Reference-21-never); [`evaluation.md`](evaluation) [\[S5\]](evaluation#v0-spike-choices)).
- **door rule** — the owner's name for a refusal: "turn this request away", about the act being recorded at the moment it is submitted, and silent about it afterwards ([Reference §21](Reference-21-never)).
- **actor** — the person, job, or system that committed an act: bound by the act's `by Shape [as name]` clause under the name `actor` (or the `as` name), a fact of the commit the binding hands in and the committer never claims, stored on a durable act like its timestamp; the security field's *principal*, under the word the spec uses ([Reference §22](Reference-22-Open-unresolved), "The actor"; OQ33, settled 2026-10-15).
- **principal** — the security field's word (JAAS, Kerberos, cloud IAM) for the identity an action is performed on behalf of; in velle the actor, above. Used in prose about the concept, never as a spelling in a spec.
- **role gate** — a prohibition on who may commit an act, spelled in the act's header (`by Administrator`, a refinement after `by`) or as a requirement over the actor in the body (`requires actor to be Administrator`); one desugaring, the same refusal ([Reference §22](Reference-22-Open-unresolved), "The actor"; [§21](Reference-21-never)).
- **viewer** — the person a read is for: the record the binding hands the generated `read(viewer)`, bound in a visibility clause's predicate under `actor` or the clause's `as` name; the same kind of thing as an actor, seen from the read side ([Reference §8](Reference-08-Refinements), "Who may see a record"; [§22](Reference-22-Open-unresolved), "The actor").
- **visibility clause** — `visible to <Shape> [as name] [where ...]` or `visible to anyone`: on a shape body, which viewers its records are returned to; after a field, which viewers that field is returned to within its record; at the top level, the spec-wide default a shape's own clauses replace. Applied by the read surface only, never inside evaluation ([Reference §8](Reference-08-Refinements); checks [V32](checks#v32--every-readable-shape-declares-its-visibility)).
- **the API layer** — a running system's operations in wire terms, built from the compiled model so one implementation serves every spec: commit an act, read a record, run a query, count, fire a tick, describe the model (`apis/json`, `velle.api.VelleApi`). A transport maps requests onto it: the REST controller and the GraphQL schema of [Serving a system](Serving-a-system). It names no framework, and every call through it takes the system's lock.
- **actor resolver** — the one bean a Spring Boot application declares to say who is calling: a function from the HTTP request, as the application's own security established it, to a reference to the actor's record ([Serving a system](Serving-a-system), "Who is calling"). Run once per request; the REST controller and the GraphQL engine both read what it found.
- **the engineer's view** — a read with no viewer: the generated system's `read`, unfiltered, the engineer reading the store they own. Not an identity; what a job that reads uses ([Reference §22](Reference-22-Open-unresolved), "The actor").
- **seed / seeded record** — a record that exists without any act having committed it: a migration or fixture row, the engineer's own write through the store, or `VelleSystem.seed` in memory — no door, no rule, no prohibition; outside the trust boundary by construction. How the first administrator arrives where hiring is gated on one ([Reference §22](Reference-22-Open-unresolved), "The actor"; [`evaluation.md`, "An exposed call"](evaluation#an-exposed-call)).
- **books rule** — the owner's name for a constraint: "the records never look like this", about valid committed state at every moment, and violable by later acts, ticks, and deletions ([Reference §21](Reference-21-never)).
- **drift / drift-exposed partition** — a partition of a *persistent* act over mutable state is re-evaluated at every later change to that state, so a long-handled act "drifts" between sides: a spurious refusal per flip, a stale re-fired write per flip back. Worked exhibit: `examples/partition-drift/`; flagged by advisory [A4](checks#a4--drift-exposed-act-partition).
- **handled-once act partition** — the fix idiom for drift under persistence: the partition is scoped to *unhandled* acts, each side anchored by its own rule's outcome evidence. Live in `payments.velle`.
- **anchor / anchored spelling** — the outcome-evidence conjunct (`... where not exists EditApplication for this`) that pins an already-handled act out of its partition.
- **correlation key** — a client-supplied business key (the idempotency-key pattern) a transient act carries and its outcomes copy, so callers can match responses to requests and duplicate submissions can be recognized ([Reference §4 "Transient acts"](Reference-04-State-and-commits#transient-acts-transient-act)): a documented idiom, deliberately not language machinery — the key's uniqueness is the client's to own, the dedup guard the author's to write.
- **C0 pinning** — a transient act's partitions are evaluated against the state at its arrival commit and never re-evaluated by its own consequences ([`evaluation.md`, "Transient acts"](evaluation#transient-acts-transient-act)).
- **closure / exposure closure / input closure** — what one commit carries: the act plus the inline parts its `with` declaration says arrive with it, statically shaped, with the single instance as the degenerate case ([Reference §4](Reference-04-State-and-commits); [§6 "Inline part creation"](Reference-06-Relationships#inline-part-creation-with)).
- **HOLDS / TAX / GAP** — stress-pass verdicts: the design handles the case · handles it at a cost (a restructured spelling, a coarse check to work around) · needs a new obligation or fails (a check, the runtime, or the generator is wrong or missing).
- **surface** — the set of calls available to code outside the system: the *typed surface* is the generated Kotlin API (the act input values and the `commit` overloads over them, accessors, model objects, the query API), the *query surface* or *read surface* is the part of it that gets data out, the *store surface* is the typed interface a store implements. Plain synonym: API. Used in [Reference §22](Reference-22-Open-unresolved); the reads work says "read API".

## Patterns

- **errors-are-refinements** — valid/invalid are refinement memberships, not control flow; consequence rules hang off the valid subset ([Reference §8](Reference-08-Refinements)).
- **rejection-as-data** — a refusal lands as a fact the caller reads back; nothing unwinds ([`patterns.md`, "Validation rejection is data"](patterns#validation-rejection-is-data)).
- **conditioned acceptance** — "don't accept unless X" is the *definition* of accepted, not a transaction statement ([`patterns.md`](patterns)).
- **intent-before-effect** — an external effect hangs off a durable intent fact; executing the effect is the engineer's loop observing the intent ([Reference §11](Reference-11-rule-when-on)).
- **materialize, then decide** — the transient-act idiom for async work: the handler copies the act into a durable intent within its transaction; decisions and effects hang off the intent ([`patterns.md`, "Materialize, then decide"](patterns#materialize-then-decide)).
- **ledger / episode** — history patterns: an append-only record read via `latest` · a bounded occurrence fact counted later ([Reference §12](Reference-12-Assignment), [§20](Reference-20-State-change-patterns)).
- **rung / rung recognition** — a spelling's position on the pattern spectrum (e.g. incremental vs. recompute — one description, two spellings); diagnostics point at the twin rung ([Reference §19](Reference-19-Self-referential-folds-and-tolerates)–[§20](Reference-20-State-change-patterns)).
- **predecessor recurrence** — the derived-history spelling of an order-dependent fold: a derived `previous` (`latest ... by` the ordering datum) plus self-reference one hop through it, so each record derives its running value from its predecessor's and the current total is a selector read; the served spelling for tick-cadence order-dependent folds ([Reference §19](Reference-19-Self-referential-folds-and-tolerates)).
- **arrival-order semantics** — what a commit-cadence stored fold describes: commits are serialized, so fold order is commit order — the order records arrived — which diverges from the business's ordering datum when a record arrives late ([Reference §19](Reference-19-Self-referential-folds-and-tolerates)).

## Relationships and collections

- **ownership (of a relationship)** — what `one`/`many` declare: the declaring shape's property is the stored side — rules assign it, committers supply it — and the inverse is inferred, derived, unassignable; direction is not encoded because inference makes both sides traverse ([Reference §6](Reference-06-Relationships)).
- **graduation point** — the moment an edge carries data (when, who, a grade, a quantity), it stops being a bare `many` edge and becomes a business fact with its own shape; join shapes are never ceremony, only facts ([Reference §6](Reference-06-Relationships)).
- **fan-out assignment** — a collection-path assignment (`this.invoices.customer = ...`): one write per member of the collection, one `many` hop only, the mutated field named in the statement ([Reference §6](Reference-06-Relationships); checks [V20](checks#v20--collection-assignment-legality), [V1](checks#v1--one-writer-disjointness)'s coarse extension).

## Proofs and checks

- **fail-closed** — when the prover can't decide, the spec is rejected, never silently accepted; calibration then grows the provable set.
- **calibration** — the post-v0 work of running realistic specs to learn how coarse the fail-closed checks can stay before they reject too much, and where the certificate whitelist ([V14](checks#v14--well-foundedness-coarse), [V16](checks#v16--quiescence-coarse)) grows.
- **one-writer** — every stored field has provably one writing rule per coincidence class ([Reference §12](Reference-12-Assignment); check [V1](checks#v1--one-writer-disjointness)).
- **disarm proof** — showing a rule's effects falsify its own trigger condition, breaking a re-fire cycle (check [V2](checks#v2--disarm-proof)).
- **sibling firings / siblings** — two rule firings triggered by the same commit, where neither firing caused the other, so the runtime may run them in either order ([`evaluation.md`, "Processing one commit"](evaluation#processing-one-commit) step 6). "Sibling" in these docs always means sibling rule firings, never a data relationship.
- **confluence** — sibling firings commute: every firing order yields the same outcome (check [V15](checks#v15--confluence-coarse)).
- **quiescence** — a transaction terminates: eventually no rule's condition is newly matched (check [V16](checks#v16--quiescence-coarse)).
- **discharge** — satisfy a derived proof obligation; standard proof-theory usage, throughout [Reference §18](Reference-18-Run-once-guards)–[§21](Reference-21-never). "The disarm proof discharges" = the compiler completes the required proof (the body provably falsifies its trigger); a "dischargeable state" is a trigger state the rule's own effects provably exit; an "undischarged obligation" is a compile error.
- **spent prohibition** — an established `never` used as a proof input by other analyses ("the author states the prohibition; the prover uses it," [Reference §21](Reference-21-never)); only a fully-discharged prohibition is spendable.
- **certificate** — the stated reason a static cycle provably ends, drawn from a decidable whitelist: strict descent on a creation-fixed datum plus a base case, or acyclicity supplied by a `never` prohibition. Consumed by [V14](checks#v14--well-foundedness-coarse) for definition-graph cycles and [V16](checks#v16--quiescence-coarse) for cascade quiescence; one shared vocabulary, grown by calibration.
- **pinned (firing set)** — a commit's entrant/leaver sets are computed from one pre/post diff before any sibling firing runs, so a sibling's write cannot change who fires at that commit; what it can change is read by *bodies*, which see the evolving state ([`evaluation.md`](evaluation) step 5/6; the distinction [V15](checks#v15--confluence-coarse)'s read-write leg is built on).
- **polarity (of a consult)** — which way creating an instance can move a predicate: toward true (+), toward false (−), or both/unknown (0); signs come from `exists` under negation, refinement absorption, and count comparisons. Same-direction sibling effects on one predicate cannot race ([`checks.md`](checks) [V15](checks#v15--confluence-coarse); `Validator.kt`, `canCoFire`).
- **fresh-instance argument** — a freshly created instance cannot satisfy a positive `exists ... for this` over a shape the same commit does not create, because nothing can reference it yet; so its creation provably cannot move consults gated behind such a refinement, and a fresh instance never *leaves* anything ([`checks.md`](checks) [V15](checks#v15--confluence-coarse); the [V12](checks#v12--singular-reference-proofs)/[V18](checks#v18--transient-totality-every-request-gets-a-response-coarse) family's reasoning aimed at consult analysis).
- **check IDs** — [V1](checks#v1--one-writer-disjointness)–[V18](checks#v18--transient-totality-every-request-gets-a-response-coarse) are validator errors, A-series are advisories ([A4](checks#a4--drift-exposed-act-partition) = drift-exposed partition), F-series are type/form checks; all cataloged in [`checks.md`](checks).

## Generated artifacts (`diagrams.md`, `testgen.md`)

- **projection principle** — every generated artifact (runtime, tests, diagrams) is a deterministic projection of the one authored spec: same spec in, same artifact out, regenerated at every compile — nothing is hand-maintained, so nothing can drift or disagree with a sibling ([`diagrams.md`](diagrams)).
- **may-fire / may-cause** — the artifacts' over-approximation stance, matching the runtime's relevance gating: omitting a possible consequence lies, showing an unreachable one merely hedges. Proofs sharpen the picture (one-way arrows, pruned edges, exclusive diamonds); missing proofs weaken it honestly ("may flip"), never guess.
- **membership axis** — one independently varying dimension of refinement membership on a shape; state-flow diagrams render one small machine per axis, grouping refinements onto a shared axis only when their predicates are provably disjoint ([`diagrams.md`](diagrams)).
- **rule graph** — the whole system's cause map on one page: acts and rules as nodes, "this commit's writes can change that rule's condition" as edges, guards on the edges, decision diamonds only where exclusivity is proven ([`diagrams.md`](diagrams)).

## Runtime and storage (`evaluation.md` "The universal transaction"; `compiler/src/main/kotlin/velle/Hydration.kt`)

- **envelope** — one act's transaction: the act's commit plus every consequence commit, all-or-nothing.
- **universal transaction** — the five-clause contract ([U1](evaluation#the-universal-transaction) snapshot, [U2](evaluation#the-universal-transaction) atomicity, [U3](evaluation#the-universal-transaction) serialization, [U4](evaluation#the-universal-transaction) permanence, [U5](evaluation#the-universal-transaction) no side doors) the engineer's storage must honor per envelope; normative in [`evaluation.md`](evaluation); [U3](evaluation#the-universal-transaction)'s queue-key derivation is the [U3](evaluation#the-universal-transaction) clause and [`checks.md`](checks) [A5](checks#a5--contention-width).
- **serialization domain** — the compiler-computed key set an envelope revolves around, expressed as paths from the act (`{this.account}` for a deposit): two envelopes conflict iff their domains intersect, so the domain is exactly what an implementation queues conflicting work on — derived from the envelope's footprint, never declared ([`evaluation.md`](evaluation) [U3](evaluation#the-universal-transaction); built in `compiler/.../Domains.kt`).
- **queue key** — the engineer/PO-facing name for one member of a serialization domain: work sharing a queue key is handled one item at a time in arrival order; separate queues run independently. Chosen over "lock"/"synchronized" (which name one mechanism) and "serialize" (which engineers read as data marshalling) (stated on the generated commit functions).
- **contention map** — a compilation artifact (text or diagram) stating each act's queue key in business words ("deposits queue per account"), what contends with what, and every wide domain with the read that caused it — how unintentional system-wide queueing becomes visible to engineers and product owners before production (built — `ContentionMapGen.kt`, emitted in `DIAGRAMS-<System>.md`, normative in [`diagrams.md`](diagrams)).
- **hydration / resolver** — the runtime demand-fetches the state an envelope needs through engineer-implemented storage questions: by key, by reference, by shape, captures (`Hydration.kt`, `StateResolver`; [Store API](Store-API)).
- **candidate pre-filter / superset contract** — a compiled query trusted only for *exclusion*: it may over-return, never under-return; the authoritative predicate check stays in one evaluator, in memory (`Hydration.kt`, `fetchCandidates`; `Query.kt`; [Store API](Store-API), "What a store can do").
- **polarity-dual** — how the pre-filter compiler keeps the superset contract: inexpressible predicate parts degrade to TRUE in positive position, FALSE under an odd number of negations (`Query.kt`).
- **relevance gating** — a commit evaluates only the watched conditions its mutation footprint can affect, per static read summaries (`Runtime.kt`).
- **self-contained condition** — one reading nothing beyond the base shape's own columns; the criterion for using the pre-filter soundly mid-envelope (`Runtime.kt`).
- **scan floor** — the fallback fetch: all of a shape, when no keyed or filtered path applies.
- **retraction** — deletion of a capture row at the exit commit's close: the contract's one sanctioned delete, legal because a capture is memory, not a record of the world ([`evaluation.md`](evaluation) [U2](evaluation#the-universal-transaction); `Hydration.kt`, `Retraction`).
- **session handle / store key** — runtime identity is process-local; durable identity belongs to the store and round-trips as `Ref.Persisted`/`StoreKey` (`Hydration.kt`). Session handles never reach the engineer: the surface works in references (below).

## Extension types and functions (Reference §5; the Extension types and Extension functions guides)

- **extension type** — a scalar type an engineer adds: a Kotlin class implementing `velle.ext.VelleType<T>`, registered on the classpath, named in a spec in type position like `Date`; one value and a mapping for it, never a business concept with parts ([Reference §5](Reference-05-Scalars#extension-types), [Extension types](Extension-types)).
- **extension function** — a function a spec may call that an engineer adds: a Kotlin class implementing `velle.ext.VelleFunction`, registered on the classpath, with one or more signatures written against capabilities; a predicate is one whose result is `boolean`. The builtin functions are registered functions Velle ships ([Extension functions](Extension-functions)).
- **registry** — every type and function a running compiler or system knows: the builtins, then the classes named in `META-INF/services/velle.ext.VelleType` and `META-INF/services/velle.ext.VelleFunction` across the classpath, loaded once, checked before any spec ([checks E1, E2](checks#extension-checks)).
- **capability** — one thing a spec may do with a value of a type, offered by the type's author as an interface the class implements (`Ordered`, `Summable`, `Numeric`, `Signed`, `HasCalendarDate`, `HasTimeOfDay`, in `velle.ext`) or a member of it (an operator line, a literal reader); a function or operator asks for the capability it needs of each argument, and a type that does not implement it is refused with the class and the interface named ([checks E3](checks#e3--a-capability-the-type-does-not-declare), [Extension functions](Extension-functions)).
- **store binding** — how one store holds one extension type, written in the store's own vocabulary by whoever knows the store (`velle.sql.SqlTypeBinding<T>` for the SQL stores): the kind of column, the plain value handed to it, the value back, and which comparisons the column answers faithfully; a library of its own, beside the type's ([Extension types](Extension-types), "Holding a type in a store"; [checks E4](checks#e4--a-store-holds-every-type-it-stores)).
- **`uses` line** — `uses <namespace>.<Name> [as <Name>]` at the top of a spec: picks one of two registered types sharing a name, or brings a type into the spec under another name so a shape may take its own; with a lowercase name, the same for a registered function ([Reference §5](Reference-05-Scalars#extension-types), [`grammar.md`](grammar)).

## Reads (Reference §22)

- **query** — one read request: a root (a shape or refinement), a filter in the spec's predicate language over the root's members, a required order, a page; composed by whoever asks, never declared in the spec ([Reference §22](Reference-22-Open-unresolved); `compiler/src/main/kotlin/velle/Read.kt`). Called a "query", never a "question".
- **registered query** — a query the engineer writes with the typed builder and registers under a name (`QueryRegistry`), so it is checked against the spec at the engineer's build and can be named for the store ([Reference §22](Reference-22-Open-unresolved)).
- **reference (`Ref<T>`) / model object** — one reference type for both sides of the store boundary (2026-10-13): a record's concrete shape and store key, typed by the model object it points at. A model object is the shape's generated data class, every field read once at the moment of the read, and is itself a `Ref<T>` to its record: it passes wherever a reference is taken and equals any reference to the same record (equality is identity; whether two reads differ is a comparison of fields, the engineer's call — Dave, 2026-10-13). A reference field holds a `Ref<T>`; `read(ref)` resolves it. In memory the key is the runtime's own identity ([Reference §22](Reference-22-Open-unresolved); `Hydration.kt`, `Keyed`).
- **supplied by handle / by value / in the act** — the three ways a committer gives a reference (a `one` field's, or each element of a `many` field's, the last two ways only): a handle to a record already on the books; a new value nested at the field, when the field is named in the act's `with`; a new value placed elsewhere in the same act, named by its identity in the input ([Reference §6](Reference-06-Relationships), "A reference supplied by value" and "A reference to a record arriving elsewhere in the same commit"; [Binding API](Binding-API)).
- **hidden tie-break** — the store key carried inside a page cursor beside the last row's order datums, so pages stay stable when the caller's order does not tell two rows apart; never exposed as an ordering datum ([Reference §5](Reference-05-Scalars), [§22](Reference-22-Open-unresolved)).
