# The symmetric-evaluation audit (OQ42 item 1)

**Status:** complete, 2026-08-19 — one finding found and fixed (F1), one design ruling raised and resolved the same day (R1), precision opportunities recorded (P2–P4; P5 discharged by R1's contract clause).

**The obligation.** The serialization-domain derivation walks each act's commit envelope and keys every read and write. When an envelope touches shape T and a watcher over a different base B consults T, `Domains.kt` (`subjectAnchors`) enumerates the affected subjects through recognized correlations, and the derivation's safety claim is: for every event × watcher pairing, one of three things holds —

1. the enumeration **names** the affected subject, and the evaluation there records the keyed accesses;
2. the enumeration recognizes nothing and falls to Unknown, so every read **widens** — fail-closed, sound at a throughput cost;
3. an affected subject the enumeration misses is covered by the **mirrored access**: the concurrent envelope racing on that subject evaluates the same watcher and records reads that intersect this envelope's keys — helped by writes keying the written row's correlatable references.

This audit walks that claim per construct. Method: reason from the code, then **pin every verdict with a probe spec** run through the real derivation (`SymmetricEvaluationAuditTest`), cross-checked against the example specs' generated contracts where they exercise the case. The item-2 lesson applied: argued-not-probed is how holes survive.

## Findings

**F1 (soundness — found and fixed, 2026-08-19).** Reassigning a reference (`ticket.assignee = agent`) keyed the written row and the *old* referenced row (the pre-state path), but the *incoming* row only through `correlatable` on the act's own reference — which fails for transient acts and ambiguous-inverse shapes. A reader correlating on the incoming row (`exists (Ticket where assignee == this)`) raced the write. `walkAssignment` now keys the assigned value's anchor whenever the written field is one readers can correlate on. The transient-reassignment probe fails without the fix; membership's and enrollment's generated contracts each gained the missing key.

**R1 (ruling — resolved 2026-08-19: captures are readable at admission).** Case 13. Whatever mechanism an engineer chooses to enforce the turn-taking (the contract names keys; the mechanism is theirs — locks, retries, a worker per key), it must *compute each key's concrete value before admitting the envelope's work*. A key like `reopenTicket.ticket.closedBy` hops through a capture on the `ClosedTicket` refinement — not a base column. The ruling, by the author's test "if captured fields are readable when the rule fires, then they should be readable": the condition was verified in `applyCommit`'s ordering — captures evaluate at membership entry *before* any rule fires, and leaver captures retract at the close of the commit, *after* exit rules ran ("exit rules were their last readers"). So captures are committed state — typically real columns — readable whenever a rule reads them, and admission may read them too. Capture-dependent keys are legitimate contract members; `evaluation.md` U3 now carries the clause (keys resolve at admission against pre-commit state and the act's inputs, captures included), and `DomainKeys` resolves capture hops through the declaring refinement — membership's sweep coverage doubled when it landed. A rule's `from` is unrelated: it copies a capture into an ordinary row, it never mints one.

**Precision opportunities (sound today, wider than necessary):**

- **P2.** A `this.`-rooted path inside a collection `where` is summarized against the *element* scope, misses, and sets `opaque` — making the watcher relevant to everything, so unrelated events (the rule's own body creations included) evaluate at Unknown subjects and widen. Seen in the valueCorr probe's extra width.
- **P3.** The condition route collector expands neither refinement-name collection filters (`chargeAttempts where SuccessfulCharge`) nor `is Refinement` atoms; both fall to width where a route exists to collect. The body-side collector (item 2) already expands both — the condition side could adopt the same.
- **P4.** Multi-hop reverse routes (case 6) widen; composing recognized single hops (response → attempt → order) would key instead. This is payments' `ChargeResponse` width.
- **P5 (documentation — discharged with R1).** The audit leaned on an evaluation-moment convention the contract stated only implicitly: path keys resolve against **pre-commit state plus the act's own inputs** (which is what makes case 5's old-row/new-row pair work — the pre-state path names the old row, the act reference the new one). `evaluation.md` U3 now states it, in the same clause that admits captures.

## What this audit does and does not establish

It establishes that every construct the derivation walks lands in bucket 1, 2, or 3 of the obligation — with F1 the one construct that did not, now fixed and pinned. It does not re-establish the buckets' own machinery beyond the walks above, and it inherits the commutation sweep as its regression floor: the probes pin each construct at one point; the sweep re-checks the disjointness verdicts across every example spec on every run.
