# Open questions — the directory

One line per open question (OQ) here, and nothing else. An OQ whose context fits in its line is only the line. An OQ with more lives in `questions/OQ<n>-*.md`, where the file's header states the question in plain terms before the dense part begins, and the discussion, the decisions, and the work items as `- [ ]` lines are in the file. OQ tags are stable — numbers are never renumbered or reused (next free: OQ120), so references like `OQ16` stay valid forever, and gaps in the sequence are questions already settled (table at the bottom).

**Every work item has a tag** (Dave, 2026-11-11). A work item is one action, verb-first, one line. It is a `- [ ]` line in the file of the OQ that holds its context, or, when no OQ holds it, an OQ of its own: a tagged line here, `- **OQ<n>** — <the action>`, with a file only once its context outgrows the line. A `- [ ]` line never stands here, so every piece of work can be named by a tag. This file is a directory; an OQ file holds the details. OQs are grouped by the part of Velle they change, not by where they were found; S-numbers, P-numbers, and B-numbers are findings of the peptides, pharmacy, and batches passes, recorded in OQ16's calibration record.

**When a question gets a tag:** any open design question with discussion worth keeping, or referenced from more than one doc, gets a tag and a file *at birth*; a work item that belongs under no existing OQ gets a tag at birth and a file only when its context outgrows one line — wherever it surfaced. An investigation document is a working file for an open question. When the question settles, the result promotes to the Reference or the normative docs, anything else worth keeping finds a permanent home (`patterns.md` at the root for a worked spelling, `GLOSSARY.md` for a coined term, or another open question), and the file is deleted; an investigation's reasoning is not kept. History is git.

**Lifecycle:** opened (tag + file) → discussion and items accumulate in the file → settled → the result promotes, the file is deleted, and the entry moves to the settled table with a pointer to where it retired.

The current milestone is calibrating v0 against realistic specs. Nothing here blocks the build; OQ16 — which since OQ15's settling also carries the V14 certificate-whitelist calibration — is precisely the question v0 exists to answer empirically, and `examples/peptides/` and `examples/pharmacy/` are its first two data points, and `examples/batches/` a third aimed at one modeling question (polymorphism over a shared record).
